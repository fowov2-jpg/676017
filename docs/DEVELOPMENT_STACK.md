# ВРЕМЯ ХОДОМ — Development Stack

Статус: обязательная инженерная часть ТЗ.

Последняя проверка стека: 2026-08-19.

## Цель

Ускорить разработку Android-приложения «Время ходом», сократить количество ручных регрессий и сделать каждое изменение проверяемым и воспроизводимым.

## Бесплатная production-связка

### 1. GitHub — единый источник проекта

Используем GitHub как основной source of truth для кода, задач, pull request, CI/CD и артефактов сборки.

Обязательные правила:
- `main` — стабильная ветка;
- крупные изменения — через отдельные ветки и Pull Request;
- ошибки и доработки — через Issues;
- каждая значимая правка должна проходить автоматическую проверку;
- APK/AAB для тестирования должен собираться GitHub Actions, а не только локально.

### 2. Cursor Hobby — дополнительный AI-редактор

Бесплатный Hobby-план использовать как локального AI-помощника для:
- анализа связанных файлов;
- рефакторинга;
- поиска причин ошибок;
- массовых правок;
- подготовки тестов.

Ограничение: бесплатный план имеет лимитированные Agent requests и Tab completions. Cursor не является обязательным источником истины: финальные изменения всегда фиксируются в GitHub.

### 3. GitHub Copilot Free — второй AI-слой

Использовать для:
- автодополнения;
- локального Agent/Chat в поддерживаемых IDE;
- быстрых небольших исправлений;
- генерации тестов и вспомогательного кода.

Ограничение: бесплатный тариф имеет лимиты использования. Copilot дополняет, но не заменяет код-ревью, тесты и CI.

### 4. GitHub Actions — обязательный CI/CD

После push/PR должны выполняться как минимум:
1. проверка форматирования/линтинга;
2. unit tests;
3. Android build;
4. сохранение APK/AAB как workflow artifact;
5. отдельный статус проверки для PR.

Для публичного репозитория используем GitHub Actions как основной бесплатный CI.

### 5. Figma Starter — дизайн и UI source of truth

Использовать Figma для:
- дизайн-системы;
- экранов приложения;
- компонентов;
- иконок и векторных ассетов;
- прототипов переходов;
- спецификаций размеров, отступов и состояний.

Правило: сложный экран сначала согласуется как дизайн/прототип, затем переносится в код. Нельзя улучшать визуальную часть «на глаз» непосредственно в Android-коде без зафиксированного дизайна.

### 6. Анимации — Lottie / Android Compose / VectorDrawable

Для бесплатной production-сборки основной путь:
- Lottie JSON для сложных 2D-сцен;
- Jetpack Compose animations для интерактивных состояний;
- AnimatedVectorDrawable/VectorDrawable для лёгких системных анимаций.

Цель для транспортных сцен:
- нормальные пропорции человека и транспорта;
- единый визуальный стиль;
- плавные траектории;
- независимые состояния персонажа, остановки, автобуса, метро и поезда;
- отсутствие примитивной покадровой анимации уровня статичных картинок.

### 7. Rive — только опционально

Rive можно использовать для прототипирования и экспериментов. Не считать его частью строго бесплатного production-стека: бесплатный тариф позволяет создавать проекты в редакторе, но публикация/экспорт `.riv` для shipping требует платного плана.

### 8. Firebase Spark — бесплатный мобильный backend/telemetry слой

Разрешено использовать no-cost Spark plan для функций, которые доступны бесплатно, в первую очередь:
- Crashlytics;
- Analytics;
- Cloud Messaging;
- Remote Config;
- App Distribution;
- Performance Monitoring.

Любая функция, требующая Blaze/billing, должна быть отдельно согласована до подключения.

### 9. Sentry Developer — дополнительный error monitoring

Использовать как второй слой диагностики, если его данные реально дополняют Crashlytics:
- stack traces;
- breadcrumbs;
- группировка ошибок;
- контекст релизов.

Не дублировать бессмысленно один и тот же поток ошибок в нескольких системах без пользы для диагностики.

## Обязательный цикл разработки

Каждая задача проходит цепочку:

1. Зафиксировать проблему/цель.
2. Найти все связанные файлы и зависимости.
3. Сделать изменение минимально необходимого масштаба.
4. Запустить локальные проверки.
5. Отправить изменения в GitHub.
6. Получить зелёный GitHub Actions build.
7. Проверить APK на реальном устройстве/эмуляторе.
8. Провести визуальную проверку по Figma для UI-задач.
9. Только после этого считать задачу выполненной.

## Запрещённые практики

- Массовые несвязанные изменения без проверки.
- Изменение UI без сравнения с утверждённым дизайном.
- Ручная сборка как единственный способ проверки APK.
- Добавление новой функции поверх известной критической ошибки.
- Использование платного API/сервиса без явного согласования.
- Подмена реальных транспортных данных демонстрационными данными в production-логике без явной маркировки.

## Приоритет развития «Время ходом»

1. Стабильность и исправление текущих ошибок.
2. Архитектурная чистота и предсказуемые данные.
3. Визуальное соответствие утверждённым экранам.
4. Качественные транспортные анимации.
5. Автоматизированная сборка и тестирование.
6. Только после этого — новые функции.

## Инструменты подключения

- GitHub: уже является центральным репозиторием проекта.
- Figma: использовать для макетов и дизайн-системы.
- Cursor: подключается локально к репозиторию через Git/GitHub.
- GitHub Copilot: подключается к GitHub-аккаунту/IDE.
- Firebase: подключается через Firebase project + Android configuration.
- Sentry: подключается через Sentry project + Android SDK.
