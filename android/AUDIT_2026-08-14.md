# Human Router Android audit — 2026-08-14

## Fixed in this audit

- Settings moved from a broken standalone screen to a right-side swipe drawer.
- Settings handle moved to the right edge; swipe left from the right edge opens settings; swipe right closes it.
- Route search drawer now rests horizontally centered on screen; title `Куда едем?` is centered.
- Map settings are functional and persisted with SharedPreferences:
  - rotate gestures
  - tilt gestures
- Runtime version is read from the installed runtime manifest, not hard-coded.
- `Проверить данные` triggers the unique background WorkManager runtime job.
- Runtime downloads now use HTTP connect/read timeouts and explicit HTTP status validation.
- Transient `IOException` failures return `Result.retry()` instead of permanent failure.
- Worker progress/notification updates are throttled to percent changes.
- Worker stop state is passed into the installer for cooperative cancellation.
- Runtime package integrity is checked both compressed and installed: size + SHA-256.
- Visible `© OpenStreetMap contributors` attribution added to the map UI.
- Left menu items now respond instead of silently doing nothing:
  - `Карта` closes the menu
  - `Маршруты` opens route search
  - `Транспорт` reports current implementation state
- Obsolete standalone SettingsActivity and layout removed.
- CI now runs Android Lint in addition to assembleDebug.
- CI Gradle 8.9 ZIP is verified by official SHA-256 before use.
- CI uses a stable debug signing key and a monotonically increasing versionCode based on GitHub run number.

## Connections verified

### Runtime

Source: public GitHub Release `runtime-v0.4.3`.

The release contains `manifest.json` and runtime package assets. Android uses the same release base URL from BuildConfig.

### Map

Style is bundled in APK as `asset://map_style.json` and currently points to OSM raster tiles:

`https://tile.openstreetmap.org/{z}/{x}/{y}.png`

The current user device renders the map successfully. This source is acceptable for normal interactive MVP viewing only under OSM tile usage rules. It is not suitable for bulk prefetch/offline download or guaranteed production availability.

### Background work

Runtime download uses a unique WorkManager job with network constraint and foreground `dataSync` service support for long-running download work.

## Known remaining functional gaps

These are not hidden; they are the next implementation blocks:

1. Address/place search for `Откуда` / `Куда` is not implemented yet.
2. Runtime data is downloaded and verified, but Android route calculation is not connected to those files yet.
3. Transport markers/stops/live vehicle layer are not rendered on the map yet.
4. Live transport update source/polling is not implemented yet.
5. Public OSM raster tile servers are an MVP dependency only; production/offline map support needs a self-hosted or explicitly permitted tile source.
6. A production release signing key / release build is not configured yet; current APK is a stable CI debug build.

## CI gate

Every Android push must pass:

- stable signing key preparation
- `assembleDebug`
- `lintDebug`
- APK artifact upload
- lint report artifact upload
