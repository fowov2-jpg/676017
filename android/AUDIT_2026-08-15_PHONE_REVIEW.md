# ВремяХодом — повторный аудит по реальному телефону

Дата: 2026-08-15
Основание: пользовательская оценка 2/10 и снимок экрана маршрута «Точка на карте → Поворот на Никульское».

## Что было неверно в предыдущей оценке

Зелёный CI подтверждал отсутствие падений и выполнение контрактов, но не подтверждал качество продукта. На реальном телефоне проявились дефекты, которые детерминированные скриншотные фикстуры не ловили: транспортные участки рисовались прямыми хордами, камера оставляла карте слишком мало полезной площади, а длинные цепочки этапов визуально обрезались.

## Найденные дефекты и решение

| Приоритет | Дефект | Причина | Исправление |
| --- | --- | --- | --- |
| P0 | Автобус/метро на карте выглядели одной прямой линией | `MainActivity` соединял только `from`/`to` каждого крупного участка | В модель добавлена геометрия участка; BUS/TRAM получают последовательность реальных остановок, METRO/MCC и MCD/TRAIN — последовательность станций, WALK — узлы OSM walk graph |
| P0 | Начало, пересадки и финиш не различались | Все точки рисовались одним слоем одинаковых кругов | Старт — зелёный маркер, финиш — красный, пересадки — компактные промежуточные маркеры |
| P0 | Масштаб карты был чрезмерно общим | Для верхнего UI и панели резервировалась почти вся высота экрана | Панель уменьшена и сделана адаптивной; быстрые действия скрываются на вкладке маршрутов; camera padding рассчитывается по фактической панели и системным inset |
| P1 | Этапы маршрута обрезались справа | В карточке использовалась бесконечная горизонтальная лента chip-компонентов | Этапы заменены на многострочное текстовое описание с длительностью каждого участка |
| P1 | Фильтры обрезались справа | Все фильтры находились в одной горизонтальной строке | Основные фильтры занимают равные доли ширины; дополнительные открываются через компактное меню |
| P1 | Общая длительность выглядела несогласованной с ходьбой | Ожидание транспорта входило в итог, но не показывалось | BUS/TRAM теперь сохраняют фактическое ожидание; карточка отдельно показывает ходьбу, ожидание и пересадки |
| P1 | Альтернативы повторяли подпись «быстрее» | Дополнительные кандидаты наследовали техническую цель ранжирования | Подписи заменены на «Рекомендуем», «Надёжнее», «Меньше пешком», «Меньше пересадок» или «Альтернатива» |
| P1 | Настройка «Показывать транспорт» обещала больше, чем делала | Переключатель управлял линией маршрута, а не live-транспортом | Название изменено на «Показывать маршрут на карте»; остановки уточнены как «остановки рядом» |
| P1 | Точность прибытия могла выглядеть завышенной | Значок приблизительности ставился только устаревшему наземному расписанию | Любое наземное расписание без live-данных теперь помечается приблизительным и получает явное пояснение |
| P2 | Боковая панель настроек шире части телефонов | Использовалась фиксированная ширина 340dp | Панель теперь занимает доступную ширину с безопасным левым отступом |

## Добавленные проверки

- объединение подробной геометрии нескольких участков без дублирования точек;
- сохранение геометрии активной поездки после пересоздания процесса;
- промежуточные станции MCD/TRAIN в геометрии;
- Android instrumentation: BUS и METRO обязаны вернуть промежуточные точки, BUS обязан явно вернуть ожидание;
- визуальные фикстуры получили неплоскую геометрию, чтобы прямые линии снова не прошли screenshot review незаметно.

## Честные ограничения этой сборки

- Для BUS/TRAM runtime не содержит GTFS shapes, поэтому линия проходит по реальным остановкам, но между соседними остановками остаётся прямым сегментом, а не точной осью каждой улицы.
- Нет live-положения транспорта, оперативных отмен и пробок; расписание явно обозначается плановым/ориентировочным.
- Активная поездка не является полноценной пошаговой навигацией уровня промышленного картографического сервиса: она ведёт по этапам и периодически перепланирует маршрут по геопозиции.
- Финальная продуктовая оценка возможна только после повторной установки на реальный телефон и проверки того же маршрута.
